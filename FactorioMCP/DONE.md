## Features

- [x] **RCON Client (CPX 2)** — Source RCON protocol over TCP in `Rcon/RconClient.cs` and `Rcon/RconPacket.cs`. Supports authentication, command execution, and Lua execution via `/c` prefix. Uses `BinaryPrimitives` for little-endian packet framing, async I/O throughout, and proper cancellation token support.
- [x] **Factorio Service Layer (CPX 3)** — `Services/FactorioService.cs` wrapping RCON Lua calls with typed methods: Walk, StopWalking, GetPlayerPosition, GetInventory, Craft, GetCraftingQueue, PlaceEntity, MineEntityAt, GetNearbyEntities, GetResearchStatus, ExecuteRawLua. Uses `string.Create` with `InvariantCulture` for safe double formatting in Lua scripts.
- [x] **MCP Server Hosting & Wiring (CPX 2)** — Program.cs rewritten with Generic Host, DI registration of RconClient/FactorioService, `RconConnectionService` hosted service for RCON connection on startup from environment variables, MCP server with stdio transport and assembly-scanned tool discovery. Added `ModelContextProtocol` and `Microsoft.Extensions.Hosting` packages.
- [x] **Movement Tools (CPX 2)** — `Tools/MovementTools.cs` with MCP tools: `WalkForDuration` (walk direction + seconds then stop, returns position), `StopWalking`, `GetPlayerPosition`. Uses real physics-based walking via `player.walking_state`.
- [x] **Inventory & Crafting Tools (CPX 2)** — `Tools/InventoryTools.cs` with MCP tools: `GetInventory`, `Craft` (real crafting queue via `player.begin_crafting`), `GetCraftingQueue`.
- [x] **Entity Placement & Mining Tools (CPX 2)** — `Tools/EntityTools.cs` with MCP tools: `PlaceEntity` (place from inventory at coordinates with direction, validates inventory and position), `MineEntity` (mine entity at coordinates into inventory).
- [x] **World Scanning Tools (CPX 2)** — `Tools/WorldTools.cs` with MCP tools: `GetNearbyEntities` (entities within radius), `GetResearchStatus` (current research and progress). `GetPlayerPosition` already available in MovementTools.
- [x] **Blueprint & Ghost Support (CPX 4)** — `Services/BlueprintService.cs` + `Tools/BlueprintTools.cs` with 5 MCP tools: `PlaceGhostEntity` (place transparent construction plan via `create_entity{name="entity-ghost"}`), `PlaceBlueprintString` (import and build blueprint string via `cursor_stack.import_stack` + `build_from_cursor`), `GetGhostEntities` (scan for ghost entities with optional remote center), `CreateBlueprintFromArea` (capture area as exportable blueprint string via `create_blueprint` + `export_stack`), `RevokeGhostEntity` (destroy ghost entities at position). 53 unit tests + 6 integration tests.
- [x] **Inventory Management Tools (CPX 2)** — Added 3 MCP tools to `InventoryTools.cs` and 3 service methods to `FactorioService.cs`: `DropItems` (drop items onto ground via `spill_item_stack`), `TransferAllItems` (bulk transfer entity inventory to player via iterating slots), `GetEntityInventory` (inspect entity inventory contents with slot/empty counts via `get_contents`). 28 unit tests + 3 integration tests.
- [x] **Proximity Checks (CPX 2)** — `PlaceEntityAsync` validates `build_distance`, `MineEntityAtAsync` validates `reach_distance` before executing. Added `CheckDistanceAsync` service method and `CheckDistance` MCP tool in WorldTools for pre-flight range checks. Returns clear "Out of range" errors with distances when player is too far.
- [x] **Wait / Polling Mechanisms (CPX 3)** — `Tools/WaitTools.cs` with MCP tools: `WaitForCrafting` (poll until queue empties), `WaitForPosition` (poll until player reaches target within tolerance), `WaitForTicks` (poll until game ticks elapse), `GetGameTick` (current tick). All use configurable poll interval and timeout with JSON status responses (`complete`/`arrived`/`timeout`). Added `ScriptedRconClient` test double for polling tests. 20 new tests (98 total). TOOLS.md updated with new Wait & Polling section.
- [x] **Movement Pathfinding & Obstacle Avoidance (CPX 4)** — Player gets stuck when walking into entities. Implemented stuck detection + automatic detour in the Lua `on_tick` walking handler. Tracks player position each tick; after 10 ticks with no movement, switches to a perpendicular direction for 15 ticks to navigate around the obstacle, then resumes the original direction. Alternates detour sides (left/right) on repeated stuck events. Uses `storage.walk_state` for state persistence. `WalkForDuration` MCP tool now also reports a `"stuck"` status with a warning when the player fails to move at all.
- [x] **Map / Terrain Scanning (CPX 3)** — Two new service methods and MCP tools: `ScanResources` scans for resource patches (ores, oil) within a radius, returning a summary per resource type (name, patch count, total amount, center coordinates). `ScanTiles` scans terrain tiles in an area, returning tile type counts (grass, sand, water, etc.). Both use `find_entities_filtered{type="resource"}` and `find_tiles_filtered` respectively. Added 13 unit tests.
- [x] **Player Interaction Tools (CPX 3)** — Three new service methods and MCP tools in `InteractionTools.cs`: `InsertItems` (insert items from player inventory into entity inventories — fuel drills, load furnaces, stock assemblers), `RemoveItems` (take items from entity inventories into player inventory — collect smelted plates, crafted items), `InspectEntity` (read entity status, inventory contents, burner fuel level, recipe, health, mining target). Supports 6 inventory types (fuel, furnace_source, furnace_result, chest, assembling_machine_input, assembling_machine_output). All tools prioritize non-resource entities when overlapping. Added 23 unit tests.
- [x] **Chat Message Reaction (CPX 3)** — Three new service methods and MCP tools in `Tools/ChatTools.cs`: `InitializeChatListener` (registers `on_console_chat` event handler via RCON that stores messages in `storage.chat_log`, idempotent), `GetChatMessages` (reads stored chat log with `sinceTick` filter for polling new messages, includes JSON escaping and `latest_tick` cursor), `SendChatMessage` (sends `[AI]`-tagged message via `game.print()` with Lua string escaping). Auto-initialized on RCON connection via `RconConnectionService`. Creative RCON-only workaround — no mod required. Added 18 unit tests.
- [x] **Goal Planner & State Machine (CPX 5)** — C#-side goal tracking system in `Services/GoalPlannerService.cs` with `Models/Goal.cs` data model and `Tools/GoalTools.cs` MCP tools. State machine lifecycle (Pending → Active → Completed/Failed/Suspended, with Resume support). Only one goal active at a time, auto-activation on creation. Ordered steps with sequential progression (Pending → InProgress → Completed/Skipped). JSON file persistence (`goals.json`, configurable via `FACTORIO_GOALS_FILE` env var) for resume across server restarts. Thread-safe via SemaphoreSlim. 9 MCP tools: `SetGoal`, `GetActiveGoal`, `GetAllGoals`, `AdvanceGoalStep`, `AddGoalSteps`, `CompleteGoal`, `FailGoal`, `SuspendGoal`, `ResumeGoal`. Added 36 unit tests.
- [x] **Energy Management Tools (CPX 3)** — Separate `Services/EnergyService.cs` and `Tools/EnergyTools.cs` for electric network inspection. Two service methods and MCP tools: `GetElectricNetwork` (finds nearest electric pole, reads `electric_network_statistics` flow counts with 5-second precision for production/consumption rates in watts, scans accumulators for charge levels, calculates satisfaction %), `InspectEntityPower` (entity-level power diagnostics — network connection, energy stored, buffer size, drain, generation via pcall). Uses `LuaFlowStatistics.get_flow_count` with `defines.flow_precision_index.five_seconds`, J/tick × 60 for watts conversion. Added 25 unit tests.
- [x] **Research Tools (CPX 2)** — Three MCP tools in `Tools/ResearchTools.cs`: `GetResearchStatus` (current research and progress, moved from WorldTools), `GetAvailableTechnologies` (lists technologies with prerequisites met, not yet researched, includes cost and ingredients), `StartResearch` (add technology to research queue via `force.add_research`, validates existence and not-already-researched, uses pcall for safety). Added `GetAvailableTechnologiesAsync` and `StartResearchAsync` to `FactorioService`. Added 21 unit tests.
- [x] **Raw Lua Execution Tool (CPX 1)** — `Tools/LuaTools.cs` with `ExecuteLua` MCP tool wrapping `FactorioService.ExecuteRawLuaAsync`. Includes safety warning about unsandboxed execution and game state corruption risk. Added 2 tests.
- [x] **Recipe & Technology Query Tools (CPX 2)** — `Tools/RecipeTools.cs` with three MCP tools: `GetRecipeDetails` (ingredients, products, crafting time, category, enabled status), `GetAvailableRecipes` (all unlocked recipes with category and energy), `GetTechnologyDetails` (prerequisites, effects/recipe unlocks, cost, ingredients, researched/enabled status). Added `GetRecipeDetailsAsync`, `GetAvailableRecipesAsync`, `GetTechnologyDetailsAsync` to `FactorioService`. Added 26 tests.
- [x] **Building Memory & State Tracking (CPX 4)** — `Services/BuildingMemoryService.cs` with `Models/TrackedBuilding.cs` data model and `Tools/BuildingTools.cs` MCP tools. Tracks placed buildings with JSON file persistence (`buildings.json`, configurable via `FACTORIO_BUILDINGS_FILE`). Thread-safe via SemaphoreSlim. Spatial queries: `GetAllBuildings`, `GetBuildingsNear` (radius search sorted by distance), `FindBuildingsByType`, `GetBuildingSummary` (counts by type), `UpdateBuildingLabel`, `ClearBuildingMemory`. Auto-tracking: `EntityTools.PlaceEntity` automatically records buildings on success, `MineEntity` automatically removes them. Position tolerance (0.5) handles floating-point imprecision. Added 36 unit tests (30 service + 6 integration/delegation).
- [x] **Remote Area Scanning Tools (CPX 2)** — Extended `GetNearbyEntities`, `ScanResources`, and `ScanTiles` with optional `centerX`/`centerY` parameters. When provided, scans center on the given coordinates instead of the player position, enabling long-range scouting without walking. Backward-compatible — omitting center defaults to player position. Updated `WorldTools.cs` MCP tool descriptions. Added 7 unit tests.
- [x] **WalkToPosition Tool (CPX 3)** — New `WalkToPosition` MCP tool in `MovementTools.cs` that walks toward a target position until arrival, stuck, or timeout. Auto-calculates 8-direction compass heading from current position, starts walking, polls position periodically, re-calculates direction for course correction, and detects stuck conditions (6 consecutive polls with <0.15 tile movement). Returns JSON with status (`arrived`/`stuck`/`timeout`), current position, target, distance, and tolerance. Orchestrates existing `WalkAsync`/`StopWalkingAsync`/`GetPlayerPositionAsync` service methods — no FactorioService changes needed. Added `CalculateDirection` internal static helper with atan2-based angle-to-direction mapping. Added 19 unit tests (8 direction calculation + 6 WalkToPosition behavior + 5 edge cases).
- [x] **MCP Resources (CPX 3)** — `Resources/GameStateResources.cs` with `[McpServerResourceType]` and 8 `[McpServerResource]` methods exposing read-only game state as MCP Resources: player position, player inventory, crafting queue, research status, available technologies, available recipes, electric network stats, and game tick. Registered via `.WithResourcesFromAssembly()` in Program.cs. Resources delegate to existing FactorioService/EnergyService methods — no new RCON commands needed. Added 9 tests (1 DI resolution + 8 delegation). Clients can read these via `read_resource` without making tool calls.

## Improvements

- [x] **RCON Reconnection & Resilience (CPX 2)** — `RconClient` now stores connection parameters, recreates `TcpClient` on connection loss, and retries with exponential backoff (up to 3 attempts). `ExecuteAsync` catches `IOException`/`SocketException`/`ObjectDisposedException` and auto-reconnects before retrying the command. `RconConnectionService` retries startup connection up to 5 times with backoff and logs warnings via `ILogger`. Thread-safe via `SemaphoreSlim`.
- [x] **Structured Lua Responses (CPX 2)** — All `FactorioService` methods now return JSON via `rcon.print()` instead of ad-hoc text. Responses use flat keys (e.g. `{"success":true,"entity":"stone-furnace","x":5,"y":-2}`) for reliable AI parsing. Error responses include structured `error` codes (`out_of_range`, `invalid_position`, `missing_item`, `no_entity`). TOOLS.md updated with all JSON response examples.
- [x] **MCP Tool Call Logging (CPX 2)** — Added `McpRequestFilter<CallToolRequestParams, CallToolResult>` in `Program.cs` via `WithRequestFilters` + `AddCallToolFilter`. Logs tool name and JSON-serialized arguments to stderr on invocation and completion. Uses `Console.Error` to avoid interfering with MCP stdio transport on stdout. Zero per-tool changes — all tools are covered automatically by the SDK filter pipeline.
- [x] **RCON Client Connection Logging (CPX 2)** — Added `ILogger<RconClient>` to `RconClient` with optional constructor parameter (defaults to `NullLogger` for test compatibility). Logs: initial connection attempts (Debug), successful authentication (Information), connection loss during command execution (Warning with exception), each reconnection attempt with attempt/max count (Information), reconnection success (Information), per-attempt failures with backoff timing (Warning), final reconnection failure (Error), and connection close events (Debug).
- [x] **Command Queuing & Sequencing (CPX 3)** — `Services/GameCommandQueue.cs` serializes game operations via `SemaphoreSlim` to prevent race conditions when multiple MCP tool calls arrive concurrently. All tool classes (MovementTools, InventoryTools, EntityTools, WorldTools, InteractionTools, WaitTools, ChatTools, ResearchTools, LuaTools, RecipeTools, EnergyTools, BuildingTools) use `queue.ExecuteAsync()` for exclusive execution. Registered as singleton in DI. Added 5 unit tests.
- [x] **Goal Planner Timestamps (CPX 1)** — Added `UpdatedAt` property to `Goal` model. All goal tool responses now include `CreatedAt`/`UpdatedAt` timestamps, and terminal-state responses (Complete, Fail) also include `CompletedAt`. `UpdatedAt` is set to `DateTime.UtcNow` on every mutation (AdvanceStep, AddSteps, Complete, Fail, Suspend, Resume). Added 12 unit tests.
- [x] ~~**RCON Multi-Packet Response Handling (CPX 2)**~~ — *Reverted: Factorio's RCON does not support receiving type 0 (ResponseValue) packets from clients. Replaced with single-packet reads. See Bug Fixes.*

## Bug Fixes

- [x] **RCON `game.player` is nil fix** — Discovered via live testing that `game.player` returns `nil` in RCON context (both singleplayer and dedicated server). Replaced all 12 Lua snippets in `FactorioService.cs` to use `game.connected_players[1]` which correctly resolves the first connected player. All service methods (Walk, StopWalking, GetPlayerPosition, GetInventory, Craft, GetCraftingQueue, PlaceEntity, MineEntity, GetNearbyEntities, CheckDistance, GetResearchStatus, WaitForPosition) now work against a live Factorio instance. Added 14 live integration tests in `LiveGameTests.cs` confirming all tools function correctly.
- [x] **`MineNearbyResource_AddsToInventory` integration test fix** — Test picked the first mineable entity (not closest), walked once without re-checking distance, and crashed on empty RCON response. Fixed to pick the closest entity, retry walking up to 5 times with distance re-checks, and handle empty mine responses gracefully.
- [x] **`MineEntityAtAsync` Factorio 2 API fix** — `entity.mine{inventory=player.get_main_inventory()}` fails in Factorio 2 (`"inventory" must be a script inventory or entity inventory`). Switched to `player.mine_entity(e, true)` which correctly mines as-if-player, handles inventory transfer automatically, and raises proper game events (`on_player_mined_entity`, etc.).
- [x] **`WalkAndStop_MovesPlayer` Flaky Test Fix** — Integration test failed when the player was blocked by nearby entities. Updated to try multiple directions (south, east, north, west) and succeed if the player moves in any of them. Proper diagnostic output shows how far the player moved in each attempt.

- [x] **Factorio 2 `global` → `storage` Migration** — Factorio 2 removed the `global` table and replaced it with `storage`. Fixed all Lua scripts using `global.walk_state` (in `WalkAsync` and `StopWalkingAsync`) to use `storage.walk_state` instead. This was causing `attempt to index global 'global' (a nil value)` errors during walking.
- [x] **Factorio 2 `game.active_mods` API Fix** — `game.active_mods` was removed in Factorio 2. Fixed `RawDiagnostics_CheckGameState` integration test to use `script.active_mods['base']` instead.
- [x] **`CraftAsync` Reports Success When Nothing Was Queued (CPX 1)** — `begin_crafting` returned 0 but status was `"crafting"`. Now returns `"status":"no_materials"` when `queued` is 0.
- [x] **`CraftAsync` Non-JSON Error on Invalid Recipe (CPX 1)** — Invalid recipe names caused raw Lua errors. Wrapped `begin_crafting` in `pcall` and returns `{"status":"error","error":"unknown_recipe"}` on failure.
- [x] **`MineEntityAtAsync` Cannot Mine Resource Entities (CPX 2)** — `player.mine_entity()` fails on resource entities in Factorio 2. Now detects resource-type entities and manually harvests (reads amount and products from prototype, inserts into inventory, destroys entity).
- [x] **`MineEntityAtAsync` Picks Wrong Entity When Overlapping (CPX 2)** — `find_entities_filtered` returned entities in arbitrary order, often picking ore under a drill. Now sorts entities to prioritize non-resource entities first.
- [x] **RCON Sentinel Packet Uses Invalid Message Type (CPX 2)** — `ExecuteCoreAsync` sent a sentinel `ResponseValue` (type 0) packet for multi-packet response detection (Valve Source RCON technique). Factorio's RCON only accepts type 2 (`ExecCommand`) and type 3 (`Auth`) from clients, rejecting type 0 with `RCON received an invalid message type 0`. Removed sentinel mechanism; Factorio returns complete responses in a single packet, so `ExecuteCoreAsync` now simply sends the command and reads one response.
